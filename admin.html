STUDENT INFORMATION SYSTEM

Student management

Student records, class assignments, promotion history and secure portal access are represented in the database foundation. Configure authorised staff roles before importing real student records.

The student table is ready in the database schema. A full student enrolment workflow, bulk import and record-editing interface should be implemented and tested before live school use.

PEOPLE & ORGANISATION

Teachers and staff

The system foundation supports user profiles and role-based access. Add staff through Supabase Authentication, then assign a profile role using the secure setup process in README.

TEACHING & LEARNING

Academic records

The database foundation includes classes, subjects, attendance and results. Result entry, grade calculation, report-card generation and publishing need school-specific grading rules before production use.

SCHOOL FINANCE

Fees and payments

The database foundation includes fee payment records. Connect a compliant payment provider and implement server-side payment verification before accepting real payments. Never mark a payment as paid based only on a browser response.

CONFIGURATION

School settings & integrations

Set up academic sessions, terms, grading scales, payment provider, email/SMS delivery, storage buckets, backup policy and privacy notices before launch.

Supabase URL and publishable key belong in js/config.js. Never place a Supabase service-role key in browser files.

ACCESS CONTROL

Admin team & roles

Supported role names: super_admin, school_owner, principal, vice_principal, admission_officer, accountant, teacher, librarian, hr_manager and receptionist.

Only a trusted project owner should assign privileged roles through the Supabase SQL editor or a protected server-side administration function. Do not allow users to promote themselves.

ACCOUNTABILITY

Activity log

Sensitive administrative actions should be written to audit_logs by trusted server-side functions. Browser-only logs are not tamper-proof.
